# MaxAgent 實作計劃

**目標：** 在同一個 Windows 桌面程式找出既有對話、看歷史、向原對話續派，並在完成時收取結果；再增加個人化、更多工具和遠端操作。產品需求以 [01-PRD](01-PRD.md) 為準；實際完成與證據只記在 [04-實作記錄與進度](04-實作記錄與進度.md)。本文件是 Terra 的執行入口，分批實作，按依賴接續。

**開工前先看 [目前狀態](04-實作記錄與進度.md#目前狀態)。** 本頁只記批次、依賴和做法；下表順序不能覆蓋目前狀態的交付阻塞與暫停項目。

**執行規則：** 一般檢查及低風險修正由 Terra 完成；每批記錄檔案、命令與結果、未驗證項及下一批，不加例行總指揮驗收。只有已授權的批次才開始。遇到外部阻塞，記明哪個依賴未滿足；已授權且不依賴它的批次可繼續（例如 MAX-005 等使用者實際派工時，MAX-007 可獨立進行）。不另開測試聊天、不送真實測試提示、不重送或呼叫付費模型；正式產品路徑由使用者用原本要做的任務確認。預設驗證是最短本機操作，涉及派工、權限或憑證時再加有意義的測試。不可改寫原始歷史，不用另開聊天室替代續聊。

## MAX-005A｜修復 Codex 執行檔定位（先做）

**檔案：** 新增 `desktop/codex-cli.js`；改 `desktop/harness.js`、`model-settings.js`、`main.js`、`preload.js`、`index.html`、`renderer.js`。測試沿用本機替身及受影響的 `desktop/harness.test.js`、`model-settings.test.js`（以實際檔名為準）。

1. `resolveCodexExe()` 供派工與模型清單共用：優先用使用者在設定選擇且驗證的絕對路徑，其次是有效的 `MAXAGENT_CODEX_CLI`、系統能找到的 `codex.exe`、由 Windows 已註冊的 OpenAI Codex 桌面安裝位置組出的 `app/resources/codex.exe`。不得寫死 `WindowsApps` 版本，不遞迴搜尋或複製／安裝二進位檔，不從聊天室文字或專案資料決定要執行甚麼。自動查不到時，設定提供「選擇 Codex 執行檔／檢查連線」，驗證後才儲存。
2. 用獨立的無提示 `--version`、必要時 `app-server` 初始化驗證；不要恢復對話或送任務。派工及 `model/list` 均由同一解析器拿路徑。錯誤要能分出找不到執行檔、工作目錄不存在、Windows 拒絕執行，以及已啟動但工具拒絕接收。不要把所有程序錯誤都變成「未安裝」。保留 Claude、現有工作區權限和結果確認，不自動重送。
3. **完成標準：** 在不帶 Codex 搜尋路徑的啟動環境，對已裝桌面版可取得版本或顯示明確可用的手動設定；另檢查錯誤路徑的提示、重啟保留設定，並用替身確認派工與模型查詢走同一路徑。記錄這是啟動檢查，真實派工仍由使用者以正常任務確認。**接 MAX-005B。**

## MAX-005B｜核對原工具視窗同步與同一對話重讀

**檔案：** `desktop/main.js`、`preload.js`、`controller.js`、`renderer.js`、`index.html`；必要時調整 `desktop/harness.js` 的選中對話讀取。

1. **先查 MaxAgent → 原工具。** 逐工具以一筆已存在的使用者派工核對原聊天室識別、時間及本輪新任務和回覆，必要時請使用者提供對話名稱／時間，不要重送。記錄三個結果：原紀錄有沒有同一輪、已開啟的原視窗是否自動更新、原工具切走再打開同一舊對話後是否可見。缺第一項先查派工；第一項存在且重開可見，才可確認是原視窗更新問題。沒有既有可辨識樣本時，留待使用者下一次正常任務確認。
2. **即時更新先停在能力門檻，不換掉現有派工。** Codex 已安裝的程式有官方 `app-server proxy`；本機 `app-server daemon version` 無法連接，預設連線點也不存在。除非之後能用受支援的本機接法讀到同一個已開啟對話，否則不接即時同步、不啟動另一個服務冒充原視窗。Claude 官方 `attach` 只對受管理的背景工作階段；本機 `agents --json --all` 回傳零筆，而且現有派工使用的非互動輸出及權限選項不符合直接接入背景工作階段的條件。因此先保留兩工具現有續派；原視窗需要重開時，說明是畫面更新限制，不改寫原紀錄、不模擬鍵盤發送、不另開聊天。
3. **輔助功能另做、另驗。** MaxAgent 的「重新讀取原對話」走既有 `history(key)`，不派工；回前景或所選紀錄有變動可刷新目前對話，避免反覆讀所有歷史。保留草稿和閱讀位置；以對話識別及請求順序避免串訊息。原工具重讀須從原工具重新開啟同一舊對話，MaxAgent 的按鈕不會控制該視窗。
4. **完成標準：** 兩工具分開列出「原紀錄保存／原視窗即時顯示／重開可見」各自的證據或未驗證原因。只有原視窗在同一對話不重開即可看見本輪內容，才標即時通過；缺官方支援時，交付已驗證的重讀方法，保留即時限制。用隔離紀錄確認 MaxAgent 的輔助重讀，不能代替原視窗驗證。**接 MAX-007A；介面不必等真實派工驗收。**

若舊任務缺少對應資料，不再反覆查同一筆。下一次使用者正常派工時，沿用 `desktop/main.js` 和 `desktop/result-evidence.js` 的結果核對，記錄目標工具、原對話識別、時間、可取得的輪次識別及原紀錄是否確認；若需加診斷，只保留這些資料，不存提示詞或回覆內容。原視窗是否顯示仍分開記錄。參考 [Codex 共用背景服務](https://github.com/openai/codex/blob/main/codex-rs/app-server-daemon/README.md)及 [Claude Code 背景工作階段](https://code.claude.com/docs/en/sessions#resume-a-running-background-session)。

### MAX-005B｜手動備案

## MAX-007A｜分開處理進度、正式回覆及未讀

**檔案：** `desktop/harness.js`、`renderer.js`、`index.html`、`style.css`；沿用 `desktop/layout-check.js` 和歷史測試。

1. 在 `history()` 的顯示資料增加 `kind`：`user`、`progress`、`final`、`assistant`。Codex 按已知訊息階段如 `commentary`、`final_answer` 分類；Claude 用已確認且能對應同一輪的公開回覆／完成證據，無法判斷就保留 `assistant`。只讀工具原本公開顯示的文字，保留順序；不把所有中間訊息都當正式回覆、不把最後一筆或 `idle` 當完成，也不讀取內部推理欄位。若文字相同、但進度和正式回覆屬不同類，不能因純文字去重吃掉正式回覆。
2. `renderer.js`／`style.css`：同一個可讀寬度的訊息欄內，你的訊息靠右、藍底白字；AI 靠左，無背景泡泡。正式回覆用正常字色和「正式回覆」標示；公開處理進度用較淡但可讀的字色和「處理進度」標示；未知階段顯示「AI 訊息」。沿用亮／暗配色集中設定，各狀態不能只靠顏色區分。保留聊天輸入、模型區及頁面返回。
3. 卡片頂列保留工具名稱，另放有對比的「● 未讀」徽章；在篩選旁放同符號的圖例「● 未讀：有新訊息尚未查看」。讀過後徽章消失，但「執行中／已完成」不變。保留「未讀」篩選，讓窄窗標籤能換行。
4. **完成標準：** 用包含「你 → 處理進度 → 正式回覆」及無法分類的本機紀錄檢查；在 1200 和 670px、亮／暗各看一次，文字易讀且不溢出，無新內容不誤標未讀，查看後只清除對應卡片。**接 MAX-008／009 剩餘驗證，再做 MAX-010；未解鎖的能力要記缺口，不硬做。**

**檔案：** `desktop/harness.js`（兩工具執行及歷史）、`desktop/main.js`（派工狀態）、`desktop/controller.js`／`desktop/renderer.js`（結果與未讀）；只有資料介面變更才改 `desktop/preload.js`。回歸檢查用現有 `harness.test.js`、`controller.test.js`、`fixture-electron.js`。

1. 先查 [已知派工問題](03-技術債與Bug.md) 與既有紀錄。若能識別上次目標，按原 `tool:id` 核對送出、工具接受的原 ID／輪次、原紀錄及 MaxAgent 畫面。查不到那筆時寫明缺甚麼，直接檢查程式能確認的問題；不重送，不將未明原因寫成已修。能證明原紀錄有結果而原工具畫面未更新時，分開回報原工具同步問題。
2. 在 `harness.js` 核對 Codex `thread/resume`→`turn/start`→同 ID 完成，及 Claude `--resume`→同 ID 成功結果；拒絕、忙碌、逾時、中斷或 ID 不符不可標完成。修正已定位的問題。現有兩條路徑都限制工具或檔案寫入；清楚顯示目前能力。正常開發若需要寫檔，須使用 Harness 正式的工作區權限與授權流程，未支援前不得無提示放寬，也不算已能接手這類開發任務。
3. 在 `main.js` 讓接收請求、執行中、成功但結果尚未讀到、結果已可讀、失敗可區別；不要用 `send()` 的 `true` 或舊訊息當本輪成功。從原對話重讀並核對本輪新增結果，再發畫面更新。`controller.js`／`renderer.js` 更新原卡片及目前對話；只有新結果實際被查看時才清除對應未讀，切換對話不能把甲的結果標在乙上。為後續批次保留按 `key` 取任務狀態、結果標記及可靠輪次識別的同一條資料來源。
4. 本機替身檢查成功、原 ID 不符、逾時或未收到新結果、切換對話；執行 `npm.cmd run check` 與受影響測試。**交付標準：** 使用者在正式桌面版對 Codex、Claude Code 各用一筆原本要做的任務，在同一原對話續聊、看到本輪結果及正確未讀。只有替身或獨立腳本證據時保留待驗證，不再花模型額度重跑。**下一批：MAX-007。**

### MAX-004｜可行性關卡：產品開發前完成

**要回答的問題：** MaxAgent 作為獨立 Windows 程式，能否用現有帳號向既有聊天室送出新任務，讀回同一輪結果，並判定它完成？保留現有看板；不先做桌面外殼、手機或寵物。

1. **先做零模型呼叫調查。** 優先查 Codex、Claude Code，並平行盤點 DSH、OpenCode、WorkBuddy 作備選。查原廠文件、官方原始碼（如有）、已安裝版本的 CLI 說明和既有本機紀錄。對照支援的平台、版本、登入方式及是否能從獨立程式呼叫。桌面聊天專用工具、僅有 GUI 按鈕、可讀紀錄或可新建聊天，都不能單獨證明獨立 MaxAgent 能續聊。
2. **產出逐工具能力矩陣。** 每個工具分欄記錄：發現既有聊天室、讀歷史、按原 ID 追加、取回同一輪結果、可靠完成訊號、逐聊天室模型、逐聊天室憑證。每欄標「已實測／官方有文件待實測／不支援／未知」，附證據、版本和可重現方法；未知不可算通過。現有看板只證明三種來源可讀部分紀錄，未證明完整歷史或寫入。
3. **只對最有希望的兩種工具做一次合併實測。** 優先沿用各工具既有的隔離聊天室；找不到才把新建測試聊天列入預算。先用既有紀錄確認原 ID 和歷史，再由獨立程式送一則極短任務，請它依前文回傳固定短字串。以同一次呼叫驗證前文仍可用、同一原 ID 下出現結果、完成訊號對應同一輪。測試提示不改檔、不操作真實聊天室。預設不啟動模型；如需可能計費的驗證，先一次列明工具、聊天室、呼叫次數和預算上限供授權。建議上限：每個入選工具一輪續聊、合計兩輪；建立種子對話或重試另列入上限，沒有授權就不執行。
