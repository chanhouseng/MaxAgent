# 工具能力與已查限制：開發前先讀

整理日期：2026-11-18。依據目前產品程式及 `04-實作記錄與進度.md` 的既有證據；本次僅整理，沒有重新操作原工具、送出任務或呼叫模型。

本文是避免重複調查的能力索引，不複製實驗日誌。詳細時間、實測與歷史保留在共用進度；Codex 早期研究另見 `Codex原對話派工調查總結.md`。不能因早期結論寫「不能」而忽略後來已打通的能力。

## 1. 「管理對話」有不同程度

1. **看得到：** 找到原 ID、名稱和歷史，不代表有寫入權。
2. **交辦工作：** 向那個原對話送一筆新任務，分開核對接收及結果。
3. **改工作設定：** 更改原對話模型、連線、推理強度；能派工不等於能改設定。
4. **全面安排生命週期：** 建立工作會話、排隊、取消、重啟恢復，以及控制誰能寫入。現有三個桌面工具沒有全部達到這一層。

「保留舊對話入口」只是保留使用者現在查看／操作舊聊天室的功能。新版首頁可以以項目為中心，舊聊天室另有可打開的位置；確切位置尚未設計定案。不是刪掉舊對話、不是強迫使用者操作終端，也不是承諾 MaxAgent 能接管全部桌面會話。

## 2. 現有桌面原對話的能力邊界

| 能力 | Codex 桌面 | Claude 桌面 Code 對話 | DSH 桌面 |
| --- | --- | --- | --- |
| 讀原 ID、名稱及歷史 | 已有讀取及既有紀錄證據。 | 已有讀取及原桌面會話身分核對。 | 已有摘要／歷史讀取；配對成功後另可由原 Host 讀取。 |
| 向同一原對話派工 | 已有一般續派、原佇列與桌面通道；有真實成功證據，依入口及版本限制使用。 | 本機 peer 傳訊已接入，有同一原對話接收及結果的真實證據；正式畫面與忙碌／拒收端到端未全面確認。 | 已有配對擴充及原 Host 派工；真實安裝包載入與替身流程有證據，使用者真實模型派工未確認。 |
| 原對話被桌面持有時 | 不能再用第二個 app-server 強行恢復；已有原佇列／特定版本桌面持有者通道，不能一概說仍完全不能派工。 | 使用桌面現有程序的傳訊通道；目前只允許已確認 idle 的對話，不承諾忙碌時安全排隊。 | 擴充在原 Host 內操作已載入會話，避免另起 SDK 搶同一原對話。必須先由使用者配對。 |
| 從 MaxAgent 換模型 | 指定 Windows／Codex 版本已有真實同輪結果證據；非所有電腦及版本。佇列本身仍不能任意帶另一個模型。 | **未打通，依使用者指示暫停。** 能讀桌面模型和 CC Switch 清單，不等於能修改原桌面模型。 | 已接原 Agent 模型選擇，不改全域預設；本機替身通過。須原會話空閒且佇列為空，真實選模及原畫面同步未確認。 |
| 本輪完成 | 核對原 ID、本輪識別、正式回覆及正常完成；不能只看程序存在。 | 派工核對本輪標記、原紀錄正式回覆與正常停止；直接從原工具啟動的提醒另依 Hook 證據，不承諾所有桌面事件。 | 接收／排隊／完成分開；本機流程已接，同一請求正式回覆和正常結束才完成。真實端到端未確認。 |
| 自由取消所有原工具任務 | 只能按現有通道及證據處理所追蹤項目；取消佇列不等於中止已接收任務。 | 未證明 peer 通道可安全取消原桌面的任意任務。 | 本批未接 MaxAgent 取消 DSH 排隊。 |
| 已讀、草稿與原工具雙向同步 | 未建立可靠外部同步，沿用 MaxAgent 本機標記與草稿。 | 未找到可靠外部同步，沿用 MaxAgent 本機方案。 | 本批未做原工具已讀及草稿同步。 |

上表 Claude 換模欄不包含「在 MaxAgent 自己啟動的新程序指定模型」；那是另一種執行方式，不能用來宣稱控制了目前桌面原對話。

## 4. 新版「MaxAgent 管理的工作會話」仍需實作與驗證

這個方向是讓 MaxAgent 從一開始建立並持有自己的工作會話，使用者在 MaxAgent 圖形介面操作。它不需要先拿走目前桌面持有的同一條控制連線，但也不是現成已完成的解法。

| 工具 | 新模式可研究的基礎 | 仍未完成的部分 |
| --- | --- | --- |
| Codex | 既有 app-server 管理自己啟動的程序、原 ID 與本輪事件。 | 項目建立工作會話、模型／登入隔離、檔案附件、排程、取消、重啟復原、其他程序佔用處理；不是直接沿用舊對話就全部具備。 |
| Claude Code | SDK Query 有模型控制；當程序由 MaxAgent 建立及持有時，不必從外面搶桌面 Query。 | 真正的受管執行器、現有登入／代理的隔離核對、模型相容、結果、取消及復原。自訂 API Key 曾受設定衝突阻塞，不能宣稱已解。 |
| DSH | 現有配對能操作原 Host 已載入對話。 | 自動建立角色會話、完整生命週期、取消及真實協作尚未接入；不承諾與 Codex／Claude 有相同 API。第一批不必三工具同時完成。 |

新舊模式不應默默轉換或搬移歷史。未驗證的工具不能被協調 Agent 自動當成可用工作者。內建模型與連線管理，也不會自動補上各工具缺少的控制能力。

## 5. 後續開發的免重查規則

1. 開始工具接入工作前，先讀本索引，再讀共用進度的最新同工具章節；歷史失敗與後續成功都保留。
2. 只在有新入口、明確變更的版本行為或具體新錯誤時重查，先寫出和上次不同的證據。使用者另行要求的新調查仍可做，但不把舊方法原樣再跑一輪。
3. 不把「未驗證」寫成「已失敗」，也不把安裝包有函式、替身通過或能讀歷史寫成「真實可用」。
4. 不以開新／複製對話、刪鎖、關閉原工具、改全域設定或自動重送，冒充原對話控制已修復。
5. 本次不增加產品功能或真實測試。Claude 桌面原對話換模、Windows 通知、ZIP 依既有指示保持暫停。
